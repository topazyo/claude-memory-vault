# Context

- Task / focus: three customers reported being charged twice for one order
- Claude session ID: `example-session-id`
- Repo: `example-api`

# Scratch

- Duplicate charges cluster around 14:02–14:06, exactly when the payment provider had elevated
  latency. Not a coincidence worth ignoring.
- Our HTTP client retries on timeout. The provider was slow, not down — so the first request
  *succeeded* server-side, we timed out waiting, and the retry charged the card again.
- So the bug is not "the provider double-charged". It is "we asked twice and had no way to say
  these two asks are the same ask".
- Checked: the provider does support an `Idempotency-Key` header. We have never sent one.

# Decisions today (candidate for medium-term)

- A retry of a non-idempotent request is a second request unless something makes it the same
  request. A timeout tells you nothing about whether the work happened.
- Next step: send an idempotency key on every mutating call, keyed to the business operation and
  stable across retries.
